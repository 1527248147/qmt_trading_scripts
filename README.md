# qmt_trading_scripts

在 QMT **模型交易**通道上跑的**执行**脚本。它们只负责把一张已经定下来的目标清单交易掉,不负责选股——选股在上游,不在这个仓库。一个策略一个子目录。

| 目录 | 策略 | 状态 |
|---|---|---|
| [`combo_twap/`](combo_twap/) | 给定一张目标清单,在一个交易日内 TWAP 执行掉:卖出按股数清仓,买入按预算等额建仓、买不到就顺延到备选 | 模拟盘每日运行中 |

## 通用约定

所有子目录都遵守同一套规矩,新加策略照抄:

- **脚本必须是纯 ASCII**。QMT 用 GBK 读没有编码声明的文件,注释里一个中文字符
  就是 `SyntaxError`,而且要到贴进客户端才炸。改完查非 ASCII 字节数为 0。
- **`tests/` 必须全绿才能贴盘**。这些是不连柜台的离线回放,几分钟跑完。
- **`tools/` 和 `probes/` 里零 `passorder`**,只读。盘中要看什么都从这里查,
  不要临时写脚本连柜台。
- **`logs/` `archive/` 以及信号/选股结果不进 git**。它们是「某台机器某个账号某
  一天」的运行状态,不是源码。`.gitignore` 在仓库根,对所有子目录生效。
- **阶段边界按墙钟判定,不按 K 线标签**。QMT 会把正在形成的那根 K 线标成它的
  收盘分钟,K 线时间比墙钟快 1–2 分钟。

## 环境

- QMT 客户端「模型」模块,周期设 1 分钟,绑定账号运行。不需要独立交易权限。
- `tools/` 里的只读查询走 miniQMT(`xtquant`),解释器是
  `C:\QMTGTHT\bin.x64\python.exe`(Python 3.6.8,匹配 `cp36` 的 .pyd)。
  注意 miniQMT 和模型交易**不能同时开**,开一个会停掉另一个。
