# combo_twap — 盘中 TWAP 建仓 / 清仓执行脚本

给定一张**目标清单**,在一个交易日内把它执行掉:

- **卖出**:`SELL_TARGETS = {代码: 股数}` — 把这些持仓在当天清掉
- **买入**:`TARGETS = [代码, ...]`(按优先级排序)+ `SLOTS` + `BUY_BUDGET` — 等额买入前 `SLOTS` 只,买不到的顺延到后面的备选

清单从哪来、为什么是这些票,脚本一概不管,那是上游选股的事。这里只解决**执行**:
怎么把量拆开、什么价挂、挂不上怎么办、涨跌停/停牌/柜台拒单怎么办、断线重启怎么
接上。

跑在 QMT 客户端内置的「模型」模块里,周期 1 分钟,**不需要独立交易/miniQMT 权限**。

## 一、一天是怎么走的

两边都把一天切成几段。**段的边界按墙钟判定,TWAP 进度按 K 线时间判定** —— 这两个
不是一回事,见下面「时钟」一节。

### 卖出

| 阶段 | 墙钟 | 干什么 |
|---|---|---|
| **TWAP** | 09:30–14:00 | 按时间进度切片卖,参与率 ≤ 上一根完成 1m bar 成交量的 **10%**,单笔 ≥ 100 股 |
| **RUSH** | 14:00–14:54 | 目标变成**全部剩余**;取消最小切片限制,参与率放宽到 **30%**;**价格方式不变**,仍然被动挂 —— 这是「切得更大」,不是「挂得更差」 |
| **CANCEL** | 14:54–14:57 | 撤掉所有挂着的单,**不发新单** |
| **AUCTION** | 14:57–15:00 | 剩下的全部**一次性**以**跌停价**送进收盘集合竞价 |

### 买入

| 阶段 | 墙钟 | 干什么 |
|---|---|---|
| **TWAP** | 09:30–14:00 | 同上,参与率 ≤ 10%,单笔金额 ≥ 2,000 元 |
| **收尾** | 14:00–14:57 | 目标变成全额;取消 2,000 元下限(否则差一点的名字会等到收盘也发不出去);`TOPUP` 补零头、`RETIRE` 结案 |
| **AUCTION** | 14:57–15:00 | 还差的按**涨停价**补一次,按可用资金封顶 |
| — | 14:57 起 | `NO_CANCEL_AFTER`,不再尝试撤单 |

### 为什么 CANCEL 必须在 14:57 **之前**落地

沪深北三所的收盘集合竞价是 14:57–15:00,这三分钟**只接受新单,拒绝撤单**。如果
到 14:57 才去撤,撤单会被拒,老的被动单还活着,而竞价单会**叠在它上面** —— 那是
卖两遍,不是清场。

### 为什么竞价用跌停价不等于「按跌停价卖」

集合竞价是**所有成交撮合在同一个价格**上,由最大成交量决定。挂在跌停价的单等于说
「不管最后清算价是多少都成交我」,实际**按清算价成交**。真的会成交在跌停价的,只有
本来就封死跌停的票 —— 那种票本来也卖不掉。

买入侧对称:竞价用涨停价挂,同样是按清算价成交,只是保证排得上。

## 二、时钟:K 线时间 ≠ 墙钟

**QMT 会把正在形成的那根 K 线,标成它的收盘分钟。** 所以标着 `145700` 的那根,大约
在北京时间 **14:55:58** 就送到脚本手里了 —— K 线标签比墙钟快 1–2 分钟。

2026-08-24 实测:

```
墙钟 13:58:58 -> 收到标着 140000 的 bar
墙钟 14:54:58 -> 收到标着 145600 的 bar
墙钟 14:55:58 -> 收到标着 145700 的 bar
```

那天集合竞价因此在 **14:55:58** 就打了出去,比 14:57 早了整整一分钟。此时还是连续
竞价时段,而**连续竞价里一张跌停价限价卖单就是市价单** —— 八笔全部成交在跌停价上,
688800 以 50.85 卖了 222 股,当时买一在 64.30。那一笔 23,092 元的切片亏了 **4,017 元**。

所以现在的规矩是:

- **「现在能不能连续交易 / 还能不能撤单 / 竞价开了没」→ 墙钟** (`_wall_hhmmss()`)
- **「TWAP 应该走到几成了」→ K 线时间**

混用这两个,就是 8/24 那笔钱的来历。

## 三、切片怎么算

### 卖出

```
frac  = min(1.0, 当前会话分钟 / 180)          # 分母是 180 个交易分钟,不是 270
目标  = 本名总量 * frac
delta = 目标 - 已卖 - 挂单中
切片  = min(delta, 上一根完成 bar 成交量 * 参与率)
```

**分母是 180**:09:30–11:30 (120) + 13:00–14:00 (60)。用 270 会让进度看起来永远超前,
我本周为此误报过好几次「进度领先」,实际是落后的。

### 买入

```
每名预算 = BUY_BUDGET / SLOTS
股数目标 = 每名预算 / 现价        <- 每根 bar 重算
delta   = TWAP目标 - max(当前持仓 + 挂单, 已发出, 今日已成交)
```

`delta` 取那个 `max` 里最大的一项,是为了**宁可少买不可多买**。四个来源任何一个高
报,结果都是买少了 —— 那由顺延和收尾阶段兜住;而买多了没人兜。

⚠️ **股数目标随价格反向漂移**。预算是固定金额,票涨了就需要更少的股数。一只票 10:00
「还差 300 股」,到 14:00 可能一股没买也变成「还差 0 股」,这是正常的,不是漏单。
`RETIRE` 日志会把首次定价时的目标一并打出来,就是为了让这件事可查 —— 2026-08-25
有四只票这么结案,因为当时没打这行日志,收盘后完全对不上账。

## 四、定价:QUEUE / COMPETE,盘中可切

`price_mode.txt` 一行字,**每根 bar 重读一次**,改完存盘即时生效,不用重贴脚本。

| 模式 | prType | 行为 | 代价 |
|---|---|---|---|
| **QUEUE**(默认) | 卖 4 / 买 6 | 挂在卖一 / 买一,排队等 | 几乎不付点差,但可能一直不成交 |
| **COMPETE** | 14 | 对手价,直接吃掉对面 | 立刻成交,付半个点差 |

2026-08-04 实测 COMPETE:分钟内 100% 成交,10.37 元的票成本 4.8bp,2.09 元的票 24.0bp。

格式(可以只改某一只):

```
COMPETE              <- 裸词:所有票的默认
300363.SZ=QUEUE      <- 单只覆盖
# 井号后是注释
```

**写错的行会被忽略,不会猜。** 这个文件决定真金白银怎么定价,一个笔误绝不能悄悄
改掉挂单方式。

几个参数跟着模式一起翻转,不是简单放宽:

| | QUEUE | COMPETE |
|---|---|---|
| 点差过滤 `MIN_SPREAD_TICKS` | **0**(关) | 3 |
| 干等放弃 `NO_FILL_GIVEUP_MIN` | 实质关闭 | 120 分钟 |

点差过滤存在的意义是「别去吃一个很宽的价差」。QUEUE 根本不吃对面,宽价差反而正是
它要赚的那部分,这时候还缩手就是反的。

### 点差过大就不交易(只在 COMPETE 下生效)

对手价是**主动吃掉对面**,买一卖一差多少就直接付多少。所以 COMPETE 下有一道保护:
**这一分钟的盘口太宽就跳过,不发单,下一根 bar 重新判**。

触发要**两个条件同时成立**,单独一个都不算:

```
ticks = (卖一 - 买一) / 0.01           >= MIN_SPREAD_TICKS  (3)
bps   = (卖一 - 买一) / 中间价 * 10000 >  MAX_SPREAD_BPS    (50)
```

两个条件是"与"的关系,因为它们各自单独都会误判:

- **只看 bps**:2.00 元的低价股,一个最小变动单位就是 50bps,盘口再正常也天天触发。
- **只看 ticks**:500 元的高价股,3 个 tick 只有 0.6bps,那根本不宽。

所以要求「既有 3 个 tick 那么宽,又占到中间价 50bps 以上」才算真的宽。

几个边界:

| 情况 | 行为 |
|---|---|
| **QUEUE 模式** | `MIN_SPREAD_TICKS = 0`,**整个过滤关闭**。挂在买一/卖一根本不吃对面,宽价差正是要赚的那部分 |
| **14:45 之后**(`SPREAD_GUARD_UNTIL`) | **过滤关闭**。收盘在即,有什么价接什么价,把量做完比省点差重要 |
| **盘口读不到** | **fail open** —— 不判为宽,照常发单。宁可少一层保护,也不能因为行情缺一条 tick 就整天不交易 |

盘口从"能读"变成"读不到"(或者反过来)时会**按代码单独**打一行日志:

```
NOTE: 920002.BJ has no usable tick/touch -> SPREAD FILTER INACTIVE FOR THIS NAME
tick/touch OK 601398.SH -> spread filter live (bid 7.98 ask 7.99)
```

按代码而不是全局记状态,是因为北交所的票经常没有盘口而主板的有 —— 用一个全局标志
会在两条消息之间每根 bar 反复横跳,把一条真正的警告淹掉。而只在第一次调用时置位又
会漏掉"09:30 还好、10:00 死了"这种情况,那样过滤会在无声无息中失效一整天。

跳过时打:

```
WIDE SPREAD skip 600283.SH bid 7.85 ask 7.92 = 7 ticks / 89 bps -> retry next bar
```

**买卖两个脚本这段逻辑完全一样**,参数也一样。

> **别在 14:00 之前根据盘中读数切模式。** 8/25 我两次建议切 COMPETE(深市 10:43、
> 688800 13:24),两次都是自己恢复的。这周所有「卡住」最后都归到连接、柜台持仓数据
> 或者放弃计数器,没有一次是定价方式的问题。

## 五、涨跌停

### 卖出侧:跌停

跌停价来源,按顺序:

1. `get_instrument_detail(code)["DownStopPrice"]` —— 柜台给的,它已经知道 ST 之类的窄幅
2. 柜台没给,就按板块自己算:**北交所 30%,创业板 300/301 与科创板 688 是 20%,其余 10%**
3. 两个都拿不到 → **这只票的跌停保护直接关掉,继续尝试卖**

第 3 条是有意的:这个脚本的职责是「出得来」,所以宁可算宽一点(以为没封死,继续挂),
不能算窄(误判封死,停手)。

> 板块表里**曾经漏了北交所**,`.BJ` 掉进 10% 那一档。10.00 的前收算出 9.00 的地板,
> 而判定条件是「最高价 ≤ 地板」,于是**任何一只当天跌超 10% 的北交所票都被读成封死
> 跌停,整天不发单**,而它其实完全卖得掉。以前的篮子里有 920018.BJ 和 920002.BJ。

**封死判定**优先看实时盘口:

- 有买一 → **卖得掉**,继续
- 没有买一,但卖盘压在地板上 → 封死,本 bar 不发
- 没有买一,盘口也空 → **不算封死**(停牌或没成交的票盘口也是空的,不能当跌停处理)
- 盘口读不到 → 退而用上一根 bar 的最高价 ≤ 地板

封死期间只打一次 `LIMIT-DOWN`,松开时打 `LIMIT-DOWN RELEASED` 并恢复。**不会因为
封过跌停就把这只票判死**,每根 bar 重新判。

### 买入侧:涨停

- 封死涨停 → 本 bar 不发单,只打一次 `LIMIT-UP`
- **到 13:00(`LIMIT_UP_CUTOFF`)还是封死且一股没买到** → 放弃这个槽位,**顺延**到备选清单里的下一只
- 已经买到一部分的,收盘时按已买到的量结案,不强行补

## 六、停牌 / 全天无成交

| | 判定 | 处理 |
|---|---|---|
| **买入** | 到 **10:00**(`NO_TRADE_CUTOFF`)还是零持仓,且从开盘起**一根 1m bar 都没有** | 判为停牌,放弃槽位,**顺延**到下一只备选 |
| **卖出** | 没有专门的停牌判定 | 停牌的票 `can_use` 通常是 0、盘口是空的,会走「盘口空 ≠ 跌停」那条分支持续尝试,收盘打 `WILL NOT BE SOLD` |

卖出侧故意不做停牌判定并放弃:一只卖不掉的票,判它「停牌」还是「一直没等到买家」,
处理是一样的(继续挂着),而误判成停牌就等于主动放弃了。

## 七、交易受限 / 柜台拒单

拒单原因在 **`m_strCancelInfo`**,不在 `m_strStatusMsg` —— 这个位置找错过一次。

| 代码 | 含义 | 处理 |
|---|---|---|
| **250253** | 深圳证券账户使用信息控制标志记录不存在 | 账户注册层面的问题,**重新登录不解决**。单子在到达市场前就被拒,只有日志噪音,不亏钱。2026-08-27 全天 51 次拒单一股没卖出去;它是**间歇性**的(8/03 只有 5 次,7/31 一次没有),所以不会因为出现过就永久剔除深市票 |
| **251005** | 证券可用数量不足 | 唯一一个**真的**关于「有没有货」的原因,见下面 `can_use` 一节 |
| **251020** | 当前状态不允许撤单 | 撤单竞态,交给僵尸单防线 |
| **251259** | 无科创板交易权限 | 该槽位顺延到下一只备选 |

### `can_use` 异常兜底(卖出侧)

模拟盘柜台给的 `can_use`(可用数量)经常是错的。2026-08-31 盘前把 1000310 的
全部 39 行 dump 出来,弄清楚了它到底是什么:

```
can_use = volume + lot_floor(yesterday_volume)      <- 隔夜还原碰过的行
can_use = volume                                    <- 还原没碰过的行(3 只债券)
```

判定性的证据是 **600816**:持仓 1024 股,`can_use` 是 **2024** 而不是 2048 ——
多出来的那项是 `lot_floor(1024) = 1000`,**向下取整到整手**,而这正是「昨仓里
有多少可卖」的算法特征。所以柜台把「昨仓可卖量」算对了,然后**加到持仓上**而不是
直接用它。同一批股票数了两遍。

这不是我们对 T+1 理解错了,是**隔夜还原写库的问题**,四条证据:

1. 还原当天的**成交和委托记录都是 0 条** —— 它绕过下单路径直接写库
2. 还原没碰过的三只债券 `can_use` 正好等于持仓,**同账号同一次查询**
3. 持仓归零的死行里,昨仓/冻结/在途/市值/成本价**全是 0**,只有 `can_use` 留着
   `1 − 某个整手数` 的负数残值 —— 这个字段是增量维护的,从不与持仓对账
4. 510050 的**成本价是负数**,那一行本来就是坏的

⚠️ **一个推论**:`yesterday` 是固定的而 `volume` 随卖出下降,所以卖到一股不剩时
`can_use` 仍然等于原始持仓那么大。**它永远不会告诉你「没货了」**。不要拿它当
「还能卖多少」的信号 —— 脚本靠的是持仓和三源互证。

脚本认得这个确切签名(`_restore_artifact`),命中时**处理不变**(照样夹到持仓),
但只打一行 `NOTE`,不进 `!! ALERT` 通道。否则每天开盘那十二行一模一样的告警会把
真正没解释过的问题淹掉。

其余情况的兜底:

| 读到的情况 | 处理 |
|---|---|
| 持仓 < 0 | 回退用**昨仓**当基准,标记 `negpos` |
| `can_use` > 持仓 | **夹到持仓**,不算异常,不触发兜底 |
| `can_use` ≤ 0 但持仓 > 0 且没有挂单 | 回退用昨仓,标记 `zero` |
| 昨仓也 ≤ 0 | 判 0,标记 `nobasis` |

兜底不是无限的:**同一只票在兜底之后连续 3 次(`CU_FALLBACK_MAX_REJECTS`)因为
「数量不足」被拒,就对这只票关掉兜底**。判定只认 251005 这一类原因 —— 因为深市
250253 那种拒单跟有没有货毫无关系,拿它计数会把兜底误关掉。

兜底的动作永远是「**告警 + 换一个基准继续**」,不是「改写下单量」。实盘不该出现这些
情况,所以这些分支在实盘只会静默不触发。

## 八、挂单的生命周期

| 参数 | 值 | 作用 |
|---|---|---|
| `CANCEL_MIN_REST_BARS` | 1 | 挂上去至少停一根 bar 才考虑撤,防止刚发就撤 |
| `STALE_ORDER_MIN` | 5 | **兜底用**:盘口读不到时,按时间判老单 |
| `CANCEL_BACKSTOP_MIN` | 30 | 最后防线,无论如何这么久必撤 |
| `CANCEL_COOLDOWN_MIN`(买) | 5 | 撤完同一只票要等这么久才重挂 |
| `UNCONFIRMED_TIMEOUT_SEC` | 90 | 发出去柜台一直不确认,超时当没发过 |
| `NO_FILL_GIVEUP_MIN` | 120 / 关 | COMPETE 下两小时不成交判死;QUEUE 下等待就是策略本身,关掉 |
| `MAX_ORDER_ATTEMPTS` | 20 | 单只票发单次数上限 |
| `STALE_BAR_MAX_MIN` | 3 | 行情比当前时间旧超过这么久就不据以下单 |

**撤单的主要触发不是时间,是价格离开了挂单价。** `STALE_ORDER_MIN` 只在盘口读不到
的时候顶上。所以撤单冷却不会让单子跟不上价格 —— 价格一走就撤,冷却只防止同一分钟
内反复撤挂。

### 僵尸单

撤单请求发出去了,但**状态和剩余量都不动**。连续 `ZOMBIE_CANCEL_TRIES = 6` 次撤单
无效,且跨越至少 `ZOMBIE_MIN_AGE_MIN = 15` 个 **bar 分钟**,就把这笔单**注销**——
不再把它算作「挂单中」,让那部分量重新进入可发范围。

用 bar 分钟而不是墙钟,是因为电脑挂起会让墙钟跳变,15 分钟瞬间就满了。
(2026-07-30 一次 6 秒的挂起让 K 线标签在 3 秒真实时间里跳了 15 分钟。)

## 九、整手规则

| 板块 | 最小 | 步长 |
|---|---|---|
| 主板 / 创业板 | 100 | 100 |
| 科创板 688 | **200** | **1** |
| 北交所 `.BJ` | 100 | **1** |

**零股例外只适用于清仓**,永远不适用于减仓,也永远不适用于买入。

600816 持有 1,024 股 = 10 手零 24 股,全卖是**清仓**,所以交易所必须接受这 24 股 ——
2026-08-28 实测发出去并成交了。反过来 688800 曾经要减 3 股,被正确拒绝。

科创板「最小 200 步长 1」有个副作用:一次受参与率限制的部分成交,可能让某只票差
最多 199 股。24 元的票就是槽位的 40%。所以 14:00 之后有个 `TOPUP` 分支,在差额超过
半手时补一手,前提是超买不超过槽位预算的 15%(`TOPUP_OVERSHOOT`)。

## 十、断线 / 重启

盘中重启(关机、崩溃、重贴)会从三个地方重建「今天已经做了多少」:当天的运行日志、
开盘基准快照、逐笔成交落盘文件。`LEGACY_*` 常量保留了迁移前的旧路径,**只用于回查**,
否则重启后会把已经卖掉的再卖一遍。

2026-08-27 一天内重启了四次,零超卖。

## 十一、三源互证(卖出侧)

「今天已经卖了多少」有三个来源,这周**每一个都单独出过错**:

| 来源 | 出过什么错 |
|---|---|
| `deal` — 柜台 DEAL 查询 | 8/28 对 688800 报满 50,000,实际只成交 44,244 |
| `ours` — 本地逐笔成交落盘 | 曾被测试脚本误删(已修,现在有哨兵测试盯着) |
| `position` — 开盘基准 − 当前持仓 | 8/26 持仓查询返回空;8/27 整个下午返回负数 |

规则:

- 三个都在 → 取**中位数**(两个一致的可以否掉一个离群值,高报低报都能挡)
- 只剩两个 → 取**较小的**(低估最多换来一次废单,高估会把股票留过夜)
- 只剩一个 → 用它,并告警

任何两个对不上都打 `!! ALERT ... the three sold estimates disagree`,三个数一起打出来。

## 十二、安全阀

- **账号白名单**。同一个终端能看到模拟盘 1000003 和**实盘** 1000310,脚本必须锁定账号。
- **`MAX_TARGET_SHARES = 60000`**,任何单只目标超过就拒绝启动(防手滑多打一个零)。
- **卖出永远是明确股数,不是「清空持仓」**。测试账号里有 1,395 个不属于我们的持仓,
  603659 显示 99,986,700 股其中只有 200 股是我们的。一个「有多少卖多少」的脚本指向
  这个账号,会倒掉一亿股别人的货。
- **双重上限**:`SELL_TARGETS[code]` 和 `max(0, can_use)`,**取小**。
- **日期闸门**:不是 `CLOSE_DATE` / `OPEN_DATE` 就只报告不动手。

## 十三、盘中该看什么

所有异常都以 **`!! ALERT`** 开头,grep 这个就够了。其余关键行:

| 日志行 | 含义 |
|---|---|
| `PHASE -> RUSH` | 阶段切换,对一下墙钟是不是 14:00 |
| `LIMIT-DOWN` / `LIMIT-UP` | 封板,暂停发单 |
| `HOLD` | 这只票本 bar 没发单,后面跟原因和 delta 的全部四项 |
| `RETIRE` | 槽位结案,带 cur/tgt/short/sent 和首次目标 |
| `SKIP ... rank N` | 顺延,后面是原因 |
| `AUCTION` | 竞价单,应该出现在墙钟 14:57:00 之后 |
| `WILL NOT BE SOLD` | 收盘时仍未卖出 |
